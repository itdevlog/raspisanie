# 🏫 Telegram-бот расписания занятий (с авто-уведомлениями о заменах)

Современный и функциональный Telegram-бот для отслеживания школьного расписания занятий на базе фреймворка **python-telegram-bot** (v20+). Бот умеет парсить данные расписания из системы **Nikasoft (Ника-Люкс)**, отслеживать изменения (замены) в реальном времени и автоматически присылать уведомления пользователям о замене уроков.

Бот спроектирован с учетом поддержки нескольких школ, гибким кэшированием, встроенной базой данных на JSON, фоновым обновлением данных и полноценной панелью администратора.

---

## ✨ Основные возможности

- 🏫 **Поддержка нескольких школ**: Бот поддерживает гибкое переключение между школами (например, МАОУ СОШ №133 и МАОУ СОШ №181 г. Екатеринбурга).
- 📅 **Просмотр расписания**:
  - Расписание классов на **Сегодня**, **Завтра** и **Неделю**.
  - Просмотр расписания по **Преподавателям** (учителям).
  - Просмотр расписания по **Кабинетам** (аудиториям).
- 🔄 **Автоматическое отслеживание замен**: Фоновый сервис (`BackgroundUpdater`) каждые 30 минут проверяет актуальность расписания. При обнаружении новых замен сервис (`ExchangeDetector`) отправляет push-уведомления всем подписанным ученикам этого класса.
- 💾 **Автосохранение**: Выбранные пользователем школа и класс автоматически запоминаются в локальной базе данных (`FileDB`), избавляя от повторного ввода при каждом запуске.
- ⚙️ **Гибкие настройки**: Возможность в любой момент сменить класс, школу или настроить уведомления.
- 👑 **Панель администратора**:
  - Просмотр статуса загрузки расписаний по каждой школе.
  - Принудительное ручное обновление данных.
  - Статистика пользователей с привязанными классами.
  - Ручной запуск детектора замен через команду `/check_exchanges`.
- 📊 **Мониторинг статуса**: Команда `/status` выводит информацию об актуальности данных расписания для каждой школы (дата последнего обновления, имя файла в Nikasoft).

## 🛠️ Технологический стек

- **Язык программирования**: Python 3.10+
- **Фреймворк**: [python-telegram-bot (v20.7)](https://github.com/python-telegram-bot/python-telegram-bot) (асинхронный API, Application Builder)
- **Запросы и Парсинг**: `requests` (загрузка JS-файлов расписания Nikasoft), регулярные выражения `re`
- **База данных**: Локальная файловая БД на JSON (`FileDB`) для хранения данных пользователей
- **Временные зоны**: `pytz` (настройка под часовой пояс Екатеринбурга `Asia/Yekaterinburg`)
- **Управление конфигурацией**: `python-dotenv`

## 🚀 Установка и настройка

### 1. Клонирование репозитория
```bash
git clone https://github.com/your-username/telegram-schedule-bot.git
cd telegram-schedule-bot
```

### 2. Настройка виртуального окружения
```bash
python -m venv venv
source venv/bin/activate  # Для Linux/macOS
# или для Windows:
venv\Scripts\activate
```

### 3. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 4. Создание файла конфигурации `.env`
Создайте в корне проекта файл `.env` и заполните его следующими переменными:

```env
# Токен вашего Telegram-бота (полученный у @BotFather)
TELEGRAM_TOKEN=1234567890:ABCdefGhIJKlmNoPQRsTUVwxyZ

# ID администраторов бота через запятую (для доступа к админ-панели)
ADMIN_IDS=123456789,987654321

# Интервал фонового обновления данных расписания (в секундах). По умолчанию: 1800 (30 минут)
UPDATE_INTERVAL=1800

# Максимальное количество попыток запросов к Nikasoft при сбоях
MAX_RETRIES=3

# Логирование
LOG_LEVEL=INFO
LOG_FILE=./logs/bot.log
ADMIN_LOG_FILE=./logs/admin.log

# Пути к файлам данных
DB_PATH=./data/database.json
CACHE_PATH=./data/cache.json
```

## 🏃 Запуск бота

### Локальный запуск
Для запуска бота выполните команду:
```bash
python bot.py
```

После старта бот автоматически создаст необходимые директории (`data/`, `logs/`, `cache/`), загрузит свежие данные расписания для всех активных школ из `schools.py` и запустит фоновый поток обновления.

### Запуск в фоновом режиме (на сервере Linux)
Для постоянной работы рекомендуется настроить системную службу `systemd`.

1. Создайте файл службы `/etc/systemd/system/tg-schedule-bot.service`:
```ini
[Unit]
Description=Telegram School Schedule Bot
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/github/telegrambot
ExecStart=/root/github/telegrambot/venv/bin/python bot.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```
*(Убедитесь, что пути `WorkingDirectory` и `ExecStart` соответствуют вашему окружению).*

2. Перезапустите службы, активируйте и запустите бота:
```bash
systemctl daemon-reload
systemctl enable tg-schedule-bot.service
systemctl start tg-schedule-bot.service
```

3. Проверить логи службы:
```bash
journalctl -u tg-schedule-bot.service -f
```

## 📘 Команды бота

- `/start` — Главное меню. Основная точка входа. Здесь можно просматривать расписание на сегодня/завтра/неделю, кабинеты, учителей, менять школу или класс, а также переходить в настройки.
- `/help` — Справочное руководство для пользователя.
- `/status` — Вывод статуса синхронизации данных расписания с серверами Nikasoft.
- `/settings` — Переход в настройки (уведомления, смена школы/класса).
- `/admin` (или `/stats`) — Открытие интерактивной админ-панели (доступно только пользователям из списка `ADMIN_IDS`).
- `/check_exchanges` — Команда для принудительной проверки и рассылки замен (доступно только администраторам).

## ⚙️ Как это работает внутри (Архитектура)

1. **Загрузка данных (`DataLoader`)**:
   Поскольку расписания Nikasoft представляют собой динамические JS-файлы на удаленном сервере, `DataLoader` сначала обращается к `check_url` школы, парсит актуальное имя js-файла с помощью регулярных выражений (например, `20261013_12345.js`), скачивает этот файл из `base_url` и парсит JSON-объект `NIKA`, переводя его в Python-словарь.
   
2. **Фоновое обновление (`BackgroundUpdater`)**:
   При старте бота в отдельном демоническом потоке (`threading.Thread`) запускается бесконечный цикл. Раз в заданный интервал (по умолчанию 30 минут) он вызывает асинхронную задачу в основном цикле событий бота (`asyncio.run_coroutine_threadsafe`), скачивает свежее расписание и передает его детектору замен.

3. **Детектор изменений (`ExchangeDetector`)**:
   Детектор сравнивает структуру уроков старого сохраненного расписания и нового. При обнаружении изменений (замена кабинета, смена предмета, изменение учителя, отмена урока) он генерирует событие замены, сохраняет обновленное состояние в `data/exchange_cache.json` и инициирует рассылку через `NotificationService` всем пользователям, у которых в БД сохранен данный класс.
