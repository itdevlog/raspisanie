# Дизайн: переработка интерфейса — навигация, избранное, выбор класса, виды расписания

Дата: 2026-10-14
Статус: 📝 согласовано, ожидает плана реализации

## Цель

Сделать мобильный интерфейс расписания легче и короче:

- меньше вертикальной прокрутки и лишних переходов;
- предсказуемый возврат: «на главную» (к выбору раздела) и «к списку» (к списку
  класса/учителя/кабинета с тем же выбранным элементом);
- на главной сразу видно актуальный (текущий/ближайший) урок для **каждого**
  избранного класса/учителя/кабинета, а не только для одного сохранённого класса;
- открыть расписание можно просто — открытый элемент автоматически попадает в
  избранное;
- убрать неудачные/избыточные элементы: вид «Компактный», повтор даты в
  расписании, вынесенная на передний план статичная «смена»/«период обучения»,
  длинный скролл выбора класса.

Дизайн затрагивает несколько взаимосвязанных экранов и меняет публичный
интерфейс настроек (`ScheduleView`), поэтому это архитектурная задача: сначала
спека (этот документ), затем план реализации.

## 1. Шапка (`App.svelte`)

- Шапка **не кликабельна**. Слева — название выбранной школы и строка
  «Обновлено …» (как сейчас).
- Справа — две отдельные кнопки:
  - **«Школьный сайт»** — ссылка на `homepage_url` школы; показывается только
    когда у школы есть `homepage_url` и фича `features.homepage` включена
    (та же логика, что сейчас на главной).
  - **«Настройки»** (⚙) — переход на `/settings`.
- Шестерёнка выравнивается строго по вертикальному центру строки шапки
  (`align-items: center`, единая высота 44px у обеих кнопок, `flex: none`).
- `App` получает те же данные о школе, что уже вычисляет для фич
  (`selectedSchool`), поэтому ссылка «Школьный сайт» берётся без нового запроса.

## 2. Главная (`Home.svelte`)

- **Быстрый выбор школы** — без изменений.
- **Избранное** превращается из простого списка в набор карточек-сводок: на
  каждый избранный элемент (класс/учитель/кабинет) — своя мини-карточка
  «сейчас / далее»:
  - если по `/now` есть `current`/`next` на сегодня — показываем урок, время,
    кабинет и остаток/до начала (как сейчас в `NowWidget`);
  - если на сегодня уроков больше нет — делаем один запрос `/now` на завтра и
    показываем ближайший урок **с пометкой «Завтра»**;
  - если и завтра пусто — компактное «Уроков нет».
  - тап по карточке открывает расписание этого элемента; отдельная кнопка
    удаления из избранного сохраняется.
- **Разделы**: «Классы» и «Учителя» ставятся рядом (две колонки), добавляется
  кнопка **«Кабинеты»** (третий раздел, как на экране списка). Ссылка «Школьный
  сайт» с главной **убирается** — она теперь в шапке.
- Отдельный `NowWidget` для «сохранённого класса» убирается: его роль берут
  карточки избранного (открытый класс и так автоматически становится избранным,
  см. §6).
- Сводка по каждому избранному — отдельный компонент `FavoriteSummary.svelte`,
  который сам владеет своим запросом `/now`. Trade-off: для N избранных это до
  N (в худшем случае 2N) запросов `/now`; для обычного числа избранных
  (единицы) это приемлемо. Пакетный эндпоинт — вне объёма этой задачи.

## 3. Список (`List.svelte`)

- **Классы** — двухшаговый выбор вместо длинного скролла:
  1. полоска **параллелей** (только те номера 1–11, что есть в списке школы);
  2. после выбора параллели — **кнопки буквенных классов** этой параллели;
     тап открывает расписание класса.
  - **Поиск сохраняется**: при вводе запроса он фильтрует полный список и
    временно заменяет двухшаговый выбор строками совпадений.
  - Разбор имени класса выносится в чистый хелпер `lib/class-list.ts`
    (`parseClassName`, группировка по параллели) с юнит-тестами.
- **Учителя и кабинеты** — как сейчас: поиск + список (без параллелей).
- **Подсветка выбранного элемента**: при возврате «к списку» (§4) строка
  текущего `selection.name` помечается (`aria-current="true"` + подсветка).
  Это же поведение полезно и для избранного внутри списка.

## 4. Экран расписания (`Schedule.svelte`)

- **Две явные кнопки навигации**:
  - **«К списку»** — возвращает к списку текущего вида (классы / учителя /
    кабинеты) с сохранённым выбранным элементом (`backToList`, как сейчас);
  - **«На главную»** — возвращает на главную, выбор школы и элемента
    сохраняется (`goHome`).
  - `App` пробрасывает в `Schedule` оба колбэка (`onBack` уже есть, добавляется
    `onHome`).
- **Устранение повтора даты**: сейчас дата показывается и в навигации дня
  (`dayHeading(dayDate)`), и в заголовке тела дня (`ScheduleBody` → `dayTitle`).
  На живом экране заголовок дня в теле **подавляется** — дату оставляем только в
  навигации дня.
- **Понижение периода/смены** (сейчас — отдельные строки в начале тела дня):
  - «период обучения» из тела дня **убирается** (он статичен на весь период);
  - «смена» показывается **только для второй смены** и как компактный бейдж рядом
    с названием («Расписание 5А · смена 2»), а не отдельной заметной строкой.
- Уведомления (`Замены`/`Отмены`/каникулы/выходной/нет периода) остаются как
  есть.

## 5. Виды расписания (`Settings` + стор + `Variants`)

- Из `ScheduleView` **удаляется `'compact'`**. Остаются `cards`, `table`,
  `timeline`, `nownext`.
- **Новый вид по умолчанию** — `'cards'` (подтверждено). Меняются дефолты в
  `DEFAULT_SETTINGS`, в пропах `Schedule`, `DayView`, `WeekView`.
- **Миграция**: `sanitizeSettings` использует `pick(...)` с новым списком,
  поэтому сохранённое `'compact'` автоматически откатывается к новому дефолту —
  отдельная логика миграции не нужна, но добавляется тест.
- В недельном виде (`WeekView`) запасной вид для `nownext` (сейчас `compact`)
  меняется на новый дефолт (`cards`).
- `ScheduleBody`: удаляется `{:else}`-ветка с `ScheduleCompact`; сам
  `ScheduleCompact.svelte` удаляется.
- `Settings.svelte`: из списка `SCHEDULE_VIEWS` убирается «Компактный»; текст
  подсказки обновляется («Компактного» больше нет).
- `Variants.svelte`: удаляется вариант «1. Компактный (текущий)», остальные
  перенумеровываются 1–4, текст «в пяти оформлениях» → «в четырёх».

## 6. Авто-избранное (модель поведения)

- Правило: **любой открытый элемент** — класс, учитель, кабинет — автоматически
  добавляется в избранное. Реализация: в `App` один `$effect`, который при
  показе расписания (`school` + `name` в маршруте) вызывает
  `favorites.add(schoolId, kind, name)`. Покрывает открытие из списка, из
  избранного и по deep-link.
- `favorites.add` идемпотентен (сам проверяет наличие), поэтому повторные
  открытия ничего не дублируют. Внутри эффекта используем guard/`untrack`, чтобы
  запись в стор не создавала лишних повторных срабатываний.
- Пользователь по-прежнему может **убрать** элемент из избранного кнопкой
  удаления; при следующем открытии его расписания он снова станет избранным —
  это осознанное следствие правила «любой открытый элемент».
- Сторы `selection` и `favorites` по API не меняются.

## Подтверждённые решения

1. **Кабинеты** включаются в авто-избранное и в сводки на главной так же, как
   классы и учителя: «любой открытый элемент» — класс, учитель, кабинет.
2. **Вид по умолчанию** после удаления «Компактного» — `cards` («Карточки»).
3. **Период/смена**: «период обучения» убирается из тела дня; «смена»
   показывается только бейджем для второй смены.
