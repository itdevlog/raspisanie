# Дизайн: исправление критических багов, надёжность и развитие Telegram-бота расписания

Дата: 2026-09-11
Статус: черновик на ревью

## 1. Контекст

Telegram-бот школьного расписания (python-telegram-bot 20.7, `requests`, `pytz`,
JSON-БД `FileDB`). Поддерживает несколько школ, расписание классов/учителей/кабинетов,
фоновое отслеживание замен и уведомления. В репозитории уже есть 64 теста, ruff и CI.

Проведён аудит трёх слоёв (`services/`+`core/`+`database/`, `handlers/`, `config/`).
Найдены критические дефекты, влияющие на корректность уведомлений и отображения данных,
а также архитектурные и функциональные пробелы.

Согласовано: **формат данных и поведение менять можно свободно** (живая совместимость
не обязательна), миграцию кэшей можно делать сбросом.

## 2. Цели и критерии успеха

- Уведомления о заменах не пропускаются и не дублируются при проверке «сегодня + завтра».
- Расписание школы A никогда не показывается пользователю школы B (нет коллизии кэша).
- Смена школы не приводит к потере пользовательских настроек.
- Длительные операции не блокируют event loop Telegram.
- Пользователь может выйти из любого «залипшего» состояния (`/cancel`).
- Есть тесты-регрессии на каждый исправленный P0/P1.
- `ruff check .` чистый, `pytest` зелёный.

## 3. Не-цели (YAGNI)

- Полный переход на SQLite/ORM.
- Внедрение внешней очереди/брокера.
- Мультиязычность.
- Web-панель администратора.

Перечисленное остаётся возможными будущими задачами, но не входит в этот цикл.

## 4. Критические исправления (P0)

### 4.1 Дата-скоуп кэша детектора замен

**Проблема.** `exchange_detector.py:17,72,92` хранит `previous_schedules[school_id]`,
где значение — замены только для одной даты. `background_updater._check_exchange_updates`
(`background_updater.py:219-232`) вызывает `detect_exchanges` для одной школы дважды
(сегодня и завтра). Второй вызов перетирает baseline первого, из-за чего возможны
пропуски и ложные срабатывания.

**Решение.** Ключевать состояние по дате:

```
previous_schedules[school_id][date_str] = current_exchanges
```

где `date_str = '%d.%m.%Y'`. Сравнение идёт с
`previous_schedules.get(school_id, {}).get(date_str, {})`.

`clear_cache(school_id)` удаляет все даты школы; `clear_school_cache` — синоним.
При `load_cache` старый (плоский) формат несовместим — сбрасываем в `{}` и логируем
одно предупреждение. При `save_cache` удаляем даты старше 3 суток от текущей.

**Тесты.** Две даты для одной школы не влияют друг на друга; после смены даты baseline
корректен; prune удаляет старые даты.

### 4.2 Изоляция кэша расписания по школе

**Проблема.** `schedule_service.py:18,28,38,49,60,71` формирует ключи вида
`today_{class_name}_{date}` без `school_id`. Классы `5и`, `8б` есть в разных школах →
в пределах TTL 10 мин данные одной школы могут показаться пользователю другой.

**Решение.** `ScheduleService` получает `school_id` в конструктор. Все ключи
получают префикс школы: `{school_id}:today:{class_name}:{date}`.
Вызовы в `class_callbacks.py:70` и `class_schedule.py:85` прокидывают
`current_school_id`.

**Тесты.** Одинаковое имя класса в двух школах даёт разные записи кэша; ключи не
пересекаются.

### 4.3 `set_user_school` сохраняет документ целиком

**Проблема.** `user_service.py:26-47` пересобирает документ по white-list
(`user_id`, `current_school`, `school_classes`, `created_at`), теряя
`notification_settings` и любые будущие поля.

**Решение.** Как в `set_user_class`: если документ есть — `user.copy()`, иначе базовый
шаблон; затем точечно меняем `current_school` и `updated_at`. `update_one` upsert.

**Тесты.** Меняем школу у пользователя с `notification_settings` — настройки на месте;
новый пользователь создаётся корректно.

### 4.4 Убрать блокирующий I/O из event loop

**Проблема.** `background_updater.py:232` вызывает синхронный `detect_exchanges`
(скан всех классов, `json.dump`, файл-лог) прямо в корутине; `:260` пишет файл
синхронно. На медленном диске/многошкольи блокирует обработку апдейтов.

**Решение.**
- Вызов `detect_exchanges` обернуть в `asyncio.to_thread`.
- `log_update_activity` вызывать через `asyncio.to_thread`.
- `ExchangeDetector.save_cache` — атомарная запись (temp + `os.replace`), а сохранение
  на диск делать **один раз за цикл проверки**, а не на каждый вызов детектора.
  Вводим `detect_exchanges(..., persist=False)` и явный `flush_cache()`/`save_cache()`
  после обработки всех дат/школ.

**Тесты.** `detect_exchanges` не пишет файл при `persist=False`; `save_cache` атомарен
(нет частичного JSON при сбое); smoke — цикл обновления завершается.

### 4.5 Точечные критические правки

- `class_schedule.py:20`: `del` → `.pop('waiting_for_room_search', None)`.
- `entity_menu.py:345`: на callback-пути использовать `_edit_or_reply`, а не
  `update.message.reply_text`.
- Пагинация «Все классы»: кодировать тип расписания в callback
  `all_classes_page_{schedule_type}_{page}`; обработчик парсит тип и номер
  (`navigation_callbacks.py:93-98`, `callback_handler.py:296-299`).
- `school_selection.py:86`: проверять результат `set_user_school`; при `False` —
  показать ошибку. Вызвать `clear_search_flags`.
- `bot.py` error handler: использовать общий `GENERIC_ERROR_MSG`.

## 5. Надёжность и консистентность (P1)

- **Merge частичной загрузки.** `background_updater._perform_update`: для школ, которых
  нет в свежей выгрузке, сохранять last-known-good из старой карты; помечать такие школы
  устаревшими для `/status`. Полная ошибка (пустая выгрузка) — уведомление админам.
- **Единая инвалидация.** Метод `_on_data_replaced()` (clear `cache_service` +
  `reset_user_class_index`) вызывается и фоновым, и ручным refresh
  (`admin_callbacks.py:159-160,195-198`).
- **Экранирование Markdown.** В `notification_service.py:226,243-251` прогонять
  `class_name`, `new_subject`, `new_teacher`, `new_room` через
  `BaseScheduleService._escape_markdown`; экранировать `search_query` в `entity_menu`
  и метаданные школы в `school_info`/`menu_builder`.
- **`asyncio.Lock` на `_perform_update`** + флаг «уже выполняется» для админ-refresh,
  чтобы исключить параллельные обновления и гонки на `schools_data`.
- **Rate-limit / RetryAfter.** В `notification_service.notify_exchange_updates` и
  `notify_admins` обрабатывать `telegram.error.RetryAfter` (sleep + retry), троттлить
  рассылку; нарезка недельного расписания >4096 через `split_long_message`.
- **`FileDB`.** Ошибки `_save_data` не глотать молча: логировать и возвращать признак
  успеха; guard при пустом `dirname`; транзакционность read-modify-write (единый lock
  или `update_and_get`).
- **Batch-настройки.** Индекс получателей хранит и `notification_settings`, либо
  добавить `UserService.get_notification_settings_batch(ids, school_id)`, убрав
  линейный `find_one` на получателя (`notification_service.py:178`).
- **`DataLoader`.** Сессия на вызов/поток с закрытием в `finally`; один слой retry;
  параллельная загрузка школ с `Semaphore`.
- **mypy.** `Optional[str]` в `notification_service.py:27` и остальные аннотации.

## 6. Рефакторинг и качество (P2)

- Слить `admin_panel.py` и `AdminCallbackHandler`; одна клавиатура (не расходится),
  `/stats` показывает статистику, а не панель.
- Единая схема настроек уведомлений: убрать двойственность
  `user_preferences.notifications` vs `user.notification_settings`.
- Общие хелперы: `_find_class_id`, `_format_time_ago`, экранирование, построение
  дневной клавиатуры; объединить `room_callbacks`/`teacher_callbacks`.
- `reset_user_flow(context)` сбрасывает `waiting_for_*` и `class_digit`; вызывается
  во всех точках входа (`/start`, «Сменить класс», выбор школы, главное меню).
- Команда `/cancel` — сброс состояния и возврат в главное меню.
- Удалить мёртвый код и заменить `str(e)` на `log_user_error`.
- Репозиторий/`TypedDict` для `school_data` и пользователя; инъекция часов
  (`Clock`/`now_fn`) для детерминированных тестов границ дат.

## 7. Новый функционал (P2, после стабилизации)

1. **Напоминания об уроках** — настройка `lesson_reminders` уже есть; job по
   `LESSON_TIMES` в PTB `JobQueue`.
2. **Подписки на учителя/кабинет** — хранение подписок и рассылка по
   `TEACHERS`/`ROOMS`.
3. **Уведомления об отмене/снятии замены** — симметричный diff: элементы, исчезнувшие
   из текущего состояния, формируют событие «замена снята».
4. **«Следующая неделя»** и **«Текущий/следующий урок»** — параметр offset и расчёт
   по `LESSON_TIMES`.
5. **Тихие часы** и антифлуд.

## 8. Архитектурные изменения

- `ExchangeDetector`: состояние `{school_id: {date_str: {class: {...}}}}`, атомарная
  запись, явный flush, вызов из `to_thread`.
- `ScheduleService`: обязательный `school_id`, префикс ключей кэша.
- `BackgroundUpdater`: `asyncio.Lock`, merge частичной загрузки, единый
  `_on_data_replaced`, `to_thread` для sync-работ.
- Слой доступа: репозитории вместо прямого `user_service.db.get_collection(...)`.
- Единая точка reset состояния пользователя в `messaging.py`.
